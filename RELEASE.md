# Crucible PHP — Released capability

_As of 2026-09-25 (D-001..D-123). Every entry traces to a `DESIGN.md` decision
record (D-0xx), written before merge. This file is the record of what **shipped** — which is
now everything that was scoped; `DESIGN.md` holds the reasoning._

Crucible is an **independent test framework for PHP 8.3+**, built from the ground up, whose
observable behavior targets **drop-in compatibility with PHPUnit 13 suites**. PHPUnit is the
*specification* — never the *source*: no code, templates, doc comments, or message text are
copied from it or from any other project. Sole copyright over every line is a project
invariant.

## The proof

- **Self-hosted since Phase 4**: Crucible's own suite (1512 tests across four dialects,
  **1510 passed, 2 skipped** under `-d xdebug.mode=coverage`; two of the four skips a plain
  run reports are that one flag, and the other two are inverted — they run only when
  phpcpd-next is absent, so an installed oracle is what skips them, never an incomplete
  feature) runs on Crucible; `phpunit/phpunit` was removed from dev dependencies — zero
  PHPUnit code in the tree or in vendor.
- **Executable conformance**: 19 fixture suites run against the real oracles — the `phpunit`
  binary, and for the mocking lane the real `mockery/mockery` with its own PHPUnit — and
  against `crucible`, asserting identical outcomes, sequences, counts, issue tallies, and exit
  codes. All conform. The harness has caught real bugs on six separate occasions, and was
  itself found wrong once (D-099): keying tests by method name alone collapsed same-named
  methods from different classes into a single comparison, so a divergence in one of them
  could not be seen. Keyed by file now, which made every fixture's comparison stricter.
- **Every machine-readable output compared against the incumbent's own writer** — Clover,
  OpenClover, Cobertura, Crap4J, JUnit, TeamCity and `--coverage-xml`, by shape *and* by
  value, plus `--coverage-php` held to the properties that apply to it (D-100/D-101/D-102).
  This found four of five formats wrong, including a Clover document declaring `loc="0"` for
  every file, and a coverage ratio reading 63.6% where the incumbent reads 42.9% on the same
  code. Nothing else could have caught either: the suite was green throughout.
- **The complete PHPUnit 13 assertion surface**: all 176 `assert*` methods, the last 45 built
  and proved against the oracle case by case rather than audited away (D-099).
- **Four independent real-world benchmarks** — not a fixture built for this project, an
  unrelated project's own test suite. Each found and closed real engine gaps rather than
  confirming a suite already known to pass (D-092/D-093/D-094/D-095/D-096/D-097, and D-112
  for the fourth). Measured at pinned refs, each beside the real tool on the same checkout.
  Three need no source change; Monolog needs `compat-check --auto-fix` for five tests that
  assert PHPUnit's own internals, which is recorded in the manifest and reversible:
  `spatie/schema-org` at `a02be78…` on Pest 5.1.1 — 1926 tests, 1926 passed, 0 failed,
  against the incumbent's own 1926 and 31,059 assertions at the same commit. The project pins
  `pestphp/pest ^5.0.4` itself, so nothing was overridden. It is the case that found the
  discovery-level false green of D-112;
  `spatie/laravel-data` at 4.23.0 — 1338 tests, 1324 passed, 0 failed, 0 errors, 11 skipped,
  3 incomplete, where real Pest v4.7.8 collects the same 1338 and passes the same 1324 (its
  remaining three split as 2 incomplete + 1 todo, which moves no test between outcomes);
  Monolog at 3.10.0 — 1155 tests,
  1115 passed, 0 failed, 22 skipped, against real PHPUnit 11.5.56's own 1155 tests, 2132
  assertions and the same 22 skips at that ref, after `compat-check --auto-fix` rewrites the
  five tests asserting PHPUnit's own internals.
  `phpcpd-next/phpcpd` at v2.0, its latest release — 710 tests, 710 passed, 0 failed in 61.1s
  on Crucible 1.0.1, against the incumbent PHPUnit 11.5.55's own `OK (710 tests, 55330
  assertions)` in 57.9s. It was pinned at v1.4 (271 tests on Crucible 0.9.0) until 1.0.1. The
  `tests/_guard.php` runner-name allowlist that blocked every tag from v1.0 to v1.3 was
  replaced in v1.4 by a `SCRIPT_FILENAME` comparison, which is what makes these refs runnable;
  it needs `->phpunitCompatibility()` in `crucible.php`, because phpcpd-next's own
  `require-dev` installs `phpunit/phpunit` and D-019 otherwise stands the aliases down.
  `benchmarks/manifest.json` carries each case's ref, exact steps
  and status (`measured` / `reconstructed` / `blocked`), so a claim's standing is stated rather
  than implied.
- **The drop-in story, live**: a real Laravel 13 application runs green, unmodified —
  migrate-config'd `phpunit.xml`, factories + RefreshDatabase, Laravel's own constraints,
  JSON assertions, mocks, HTTP kernel boot — sequential and `--parallel`, with
  `composer remove phpunit/phpunit` as the only change. The browser tier runs there too:
  kernel-backed relative `visit()` URLs with the test's own state reaching the served pages
  (D-065), beside the app's real `mockery/mockery` (the aliases stand down, D-019).
- Quality gate on every phase: PHPStan max + strict rules, PER-CS 2.0 (Pint), Rector clean,
  suite green (`composer check`), conformance suite (`composer conformance`).

|---|---|---|
| 1: line coverage | **Opt-in by design** (`--coverage`, `--coverage-clover <file>`; no flag = zero overhead — a driver is an install decision and a per-test window costs real time). | 5: report tail | `--coverage-cobertura <file>` (the GitLab/Jenkins/Azure schema — classes packaged by directory, paths relative to the declared root, branch data as line-level `condition-coverage`) and `--coverage-html <dir>` (Crucible-native: self-contained static directory, inline CSS, zero scripts — index with per-file bars, annotated source pages with covered/missed/dead line classes and branch badges) | D-062 |
| 6: covers-metadata enforcement | Oracle-pinned parity (six probes): `requireCoverageMetadata` → risky without any Covers/Uses claim, with or without a coverage run; `beStrictAboutCoverageMetadata` (also CLI `--strict-coverage`, the oracle's flag) → risky naming the stray classes; `CoversClass` filters the aggregate contribution, `UsesClass` extends execution never contribution, `CoversNothing` satisfies + contributes nothing + exempt; risky discards coverage, failing keeps it. | Mutation query index | `crucible mutation-index` emits, as JSON, the inverse of the per-test line map joined with the result cache's timings: for every covered source line, the tests that ran it **fastest-first** (untimed last, ties by id — deterministic, replayable). The read-only half of mutation interop — a mutation tool loads it to run a mutant's covering tests cheapest-first and stop at the first kill. Assembled from data already recorded (`--coverage` line maps + result-cache durations); no line map present fails naming `--coverage`, no overhead on normal runs | D-077 |
| **`crucible mutate`** — mutation testing over the covered source. A token-based catalog (arithmetic, comparison, logical; each a swap table keyed by exact token text, arity-preserving so every mutant is syntactically valid, source rebuilt byte-exact) generates mutants; each runs against its D-077 covering tests fastest-first, stop-on-first-kill; the report gives the escaped mutants (the actionable gaps) and the MSI. **Warm by default** — a `pcntl_fork`ed child loads the mutant via a prepended autoloader on a unique temp path (opcache-clean, no invalidate) and runs the covering tests in-process; the parent discovers and generates but never runs, so the source stays unloaded and every mutant is warmable. **Fail-soft** where the platform cannot fork: `isSupported()` routes every mutant through a cold `crucible --worker` (`proc_open`, no pcntl) instead — degrading in speed, never correctness, never a crash. A staleness guard warns when coverage predates the source it maps. Proven warm on a scratch project (`MSI 50.0%`) and on Crucible's own source (291 mutants, real gaps found) | D-082 |

| Inline snapshots | The expected value lives in the test source, not a `.snap` file: `assertMatchesInlineSnapshot($value, $expected)` and `expect($value)->toMatchInlineSnapshot($expected)`. `-u` rewrites the source to record it — a token-precise, argument-position-aware splice (preserving the value argument of the `assert*` spelling), buffered and applied bottom-up at run end so a multi-line **nowdoc** never shifts a not-yet-applied call; a file with no recorded snapshot is byte-untouched. Same explicit-recording principle (a missing value fails and names `--update-snapshots`) and same reused engine (Exporter, ambient context, created/updated counts). Recording is sequential-run only — comparison works everywhere, but a `-u` that must record under `--parallel` fails naming the constraint rather than racing a shared file | D-076 |

## Extension surface

_The seam for third-party tools, built on the D-009 event stream. The **artifact model**:
a plugin presents typed **facts**, and Crucible tests them — the verdict, message, and exit-code
vote are always Crucible's. A check is not a test: it tallies separately, never enters the file
tree or the shard hash, and a failing/errored check votes the exit code with a **named reason**,
never a bare non-zero._
